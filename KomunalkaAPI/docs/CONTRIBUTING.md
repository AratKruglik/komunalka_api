# Керівництво з внесків до проекту

Дякуємо за інтерес до нашого проекту! Це керівництво допоможе вам зрозуміти процес внесення змін та покращень до Komunalka API.

## Робочий процес

1. Створіть форк репозиторію
2. Клонуйте форк на вашу локальну машину
3. Створіть нову гілку для ваших змін
4. Зробіть необхідні зміни
5. Напишіть тести для нових функцій
6. Переконайтесь, що всі тести проходять успішно
7. Створіть Pull Request до основного репозиторію

## Стиль коду

- Дотримуйтесь стилю коду C# від Microsoft
- Використовуйте camelCase для локальних змінних та параметрів
- Використовуйте PascalCase для назв класів, методів, властивостей та полів
- Уникайте використання скорочень
- Використовуйте зрозумілі імена змінних та методів

## Створення Pull Request

- Використовуйте зрозумілий заголовок
- Опишіть зміни детально
- Посилайтесь на пов'язані задачі чи проблеми
- Переконайтесь, що всі тести проходять успішно

## Розробка

### Створення нових функцій

1. Починайте з розробки тестів
2. Реалізуйте функціонал
3. Переконайтесь, що всі тести проходять успішно
4. Додайте документацію

### Усунення помилок

1. Спочатку створіть тест, який відтворює помилку
2. Виправте помилку
3. Переконайтесь, що тест проходить успішно

## Структура проекту

Дотримуйтесь існуючої структури проекту:

- **Controllers/**: REST API контролери
- **Models/**: Класи моделей даних
- **DTO/**: Об'єкти передачі даних
- **Data/**: Контекст бази даних та конфігурації
- **Repositories/**: Репозиторії для роботи з даними
- **Migrations/**: Міграції Entity Framework

## Комміти

- Використовуйте зрозумілі повідомлення комітів
- Дотримуйтесь формату: `тип: повідомлення`
- Типи: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

Приклади:
- `feat: додано функціонал автентифікації`
- `fix: виправлено помилку в розрахунку тарифів`
- `docs: оновлено документацію API`

## Код-рев'ю

- Будьте ввічливі та конструктивні
- Зосереджуйтесь на коді, а не на особистості
- Пояснюйте причини ваших зауважень
- Пропонуйте альтернативні рішення

## Документація

- Оновлюйте документацію при внесенні змін
- Документуйте публічні API за допомогою коментарів XML
- Підтримуйте README в актуальному стані

## Запитання

Якщо у вас є запитання, відкрийте issue або зв'яжіться з командою розробників.

Дякуємо за ваш внесок!
