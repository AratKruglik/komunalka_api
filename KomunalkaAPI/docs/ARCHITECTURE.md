# Архітектура Komunalka API

## Загальний огляд

Komunalka API побудовано на принципах багатошарової архітектури з використанням патернів Repository та Unit of Work для абстрагування доступу до даних. Така архітектура забезпечує гнучкість, тестованість та розширюваність системи.

## Шари архітектури

### Presentation Layer

- **Controllers/**: REST API контролери, які обробляють HTTP запити та відповіді
- **DTO/**: Об'єкти передачі даних для взаємодії з клієнтами

### Business Logic Layer

- **Services/**: Реалізація бізнес-логіки, валідація, розрахунки
- **Models/**: Моделі доменної області

### Data Access Layer

- **Repositories/**: Репозиторії для роботи з базою даних
- **Data/**: Контекст бази даних, міграції та конфігурації

## Основні патерни

### Repository Pattern

Репозиторії надають абстракцію для доступу до даних, що дозволяє:

- Централізувати логіку доступу до даних
- Легко замінити реалізацію доступу до даних
- Спростити тестування бізнес-логіки

```csharp
public interface IUserRepository
{
    Task<User> GetByIdAsync(int id);
    Task<IEnumerable<User>> GetAllAsync();
    Task AddAsync(User user);
    void Update(User user);
    void Delete(User user);
}
```

### Unit of Work Pattern

Unit of Work забезпечує:

- Управління транзакціями
- Централізований доступ до репозиторіїв
- Атомарність операцій з базою даних

```csharp
public interface IUnitOfWork : IDisposable
{
    IUserRepository Users { get; }
    // Інші репозиторії
    Task SaveChangesAsync();
}
```

## Потік даних

1. Клієнт надсилає HTTP запит до контролера
2. Контролер перетворює DTO в доменну модель
3. Контролер використовує репозиторій через Unit of Work
4. Репозиторій взаємодіє з базою даних
5. Результат перетворюється назад у DTO та повертається клієнту

## Структура бази даних

Проект використовує Entity Framework Core з підходом Code First для роботи з базою даних PostgreSQL.

### Основні сутності

- **User**: Користувачі системи
- **Address**: Адреси приміщень
- **ServiceCategory**: Категорії комунальних послуг
- **ServiceCounter**: Лічильники послуг
- **ServiceCounterValue**: Показники лічильників
- **Tariff**: Тарифи на послуги

## API Endpoints

API побудовано за принципами REST з використанням стандартних HTTP методів:

- GET: Отримання ресурсів
- POST: Створення ресурсів
- PUT: Оновлення ресурсів
- DELETE: Видалення ресурсів

## Розширюваність

Архітектура проекту дозволяє легко розширювати функціонал за рахунок:

- Чіткого розділення відповідальності між компонентами
- Використання інтерфейсів для ключових компонентів
- Впровадження залежностей через DI контейнер
