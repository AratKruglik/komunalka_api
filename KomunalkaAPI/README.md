# Komunalka API

API для керування комунальними послугами, рахунками та показниками лічильників.

## Технічний стек

- **Фреймворк**: ASP.NET Core (.NET 9.0)
- **Мова програмування**: C# 13.0
- **База даних**: PostgreSQL
- **ORM**: Entity Framework Core 9.0
- **Контейнеризація**: Docker

## Структура проекту

- **Controllers/**: REST API контролери
- **Models/**: Класи моделей даних
- **DTO/**: Об'єкти передачі даних
- **Data/**: Контекст бази даних та міграції
- **Repositories/**: Репозиторії для роботи з даними
- **Migrations/**: Міграції Entity Framework

## Запуск проекту

### Налаштування середовища

1. Скопіюйте `.env.example` у `.env`:
```bash
cp .env.example .env
```

2. Налаштуйте змінні середовища у файлі `.env`:
   - **База даних**: `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DATABASE`, `POSTGRES_USERNAME`, `POSTGRES_PASSWORD`
   - **JWT**: `JWT_SECRET`, `JWT_ISSUER`, `JWT_AUDIENCE`, `JWT_EXPIRATION_MINUTES`, `JWT_REFRESH_TOKEN_EXPIRATION_DAYS`

**ВАЖЛИВО**: Згенеруйте новий JWT_SECRET для продакшену (мінімум 32 символи)!

### За допомогою Docker

```bash
docker-compose up -d
```

API буде доступне за адресою http://localhost:8080 та https://localhost:8081

### Без Docker

1. Встановіть PostgreSQL
2. Налаштуйте змінні середовища у файлі `.env`
3. Запустіть міграції:

```bash
dotnet ef database update
```

4. Запустіть проект:

```bash
dotnet run
```

## Конфігурація

Конфігурація проекту здійснюється через:

- **Змінні середовища**: `.env` файл для чутливих даних (підключення до БД, JWT секрети)
- **appsettings.json**: Загальна конфігурація логування та інших параметрів
- **appsettings.Development.json**: Конфігурація для середовища розробки

### Безпека

- `.env` файл додано до `.gitignore` для запобігання комітингу чутливих даних
- Використовуйте `.env.example` як шаблон для налаштування середовища
- **Ніколи не комітьте справжні паролі та секрети в репозиторій!**

## Архітектура проекту

Проект використовує патерн Repository з Unit of Work для доступу до даних. 

### Основні концепції

- **Repository Pattern**: Абстракція для роботи з базою даних
- **Unit of Work**: Керування транзакціями та репозиторіями
- **DTO**: Використовуються для передачі даних між клієнтом та сервером

## Розробка

### Додавання нової моделі

1. Створіть клас моделі в директорії `Models/`
2. Оновіть контекст бази даних `ApplicationDbContext`
3. Створіть репозиторій для моделі в директорії `Repositories/`
4. Додайте репозиторій до `UnitOfWork`
5. Створіть DTO в директорії `DTO/`
6. Створіть контролер в директорії `Controllers/`

### Міграції

Для створення нової міграції:

```bash
dotnet ef migrations add МіграціяНазва
```

Для оновлення бази даних:

```bash
dotnet ef database update
```

## Стандарти кодування

- Використовуйте camelCase для локальних змінних
- Використовуйте PascalCase для назв класів, методів та публічних властивостей
- Додавайте анотації даних до моделей
- Використовуйте асинхронні методи для доступу до бази даних
- Документуйте публічні API за допомогою коментарів XML
